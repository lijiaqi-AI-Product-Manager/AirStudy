# 流程与数据

页面负责展示状态和接收操作；飞行服务持有实际运行状态，页面退出不会自行结束航班。客户端通过共享模型与后台交换请求，本地数据库保存可恢复的飞行状态、历史记录和偏好。

## 单人飞行

倒计时从确认的路线和预计时长开始。计时只接受实际调度的有效时间，暂停期间不累计专注时长；恢复不会把离线墙钟间隔当成已完成时间。到达后保存记录，结算操作保持幂等。

正计时使用独立归档，保存实际出发机场、座位、航向、有效时长、累计距离和位置序列。巡航、选择降落机场、进近与终态分别持久化。尚未选择目的地时保持为空。

从降落选择返回巡航时沿用同一次飞行。实际镜头回调负责恢复运行时钟；重复回调、旧页面回调和保存重试不能重复推进时间。地图缺失与地图加载失败分别记录，不生成替代地图或虚构位置。

## 所有权与并发

飞行、准备与账号绑定。账号切换会撤销旧操作的执行资格。数据库快照和追加位置在同一事务内提交，修订号冲突不会覆盖新状态。

界面和地图操作先进入主线程，再尝试取得当前所有权；持锁时不跨线程等待。过期操作不产生界面副作用，占用中的操作在锁外重试。

## 后台

后台提供账号验证、机场查询、房间与日计划能力。请求失败、权限不足和验证服务未配置均返回明确错误。客户端不会把错误回复转换为成功结果、会员资格或可用额度。

全量机场搜索按距离和稳定编号排序；客户端保留服务端顺序并继续做实际地图距离检查。本地机场选择目录与全量附近机场目录用途不同。

## 尚需接通

正计时归档已独立保存，结果页、记录列表、统计与桌面展示还需接入同一数据来源。再次起飞须等待上一轮真实终态、服务结束和占位释放，避免重复提交旧准备。
